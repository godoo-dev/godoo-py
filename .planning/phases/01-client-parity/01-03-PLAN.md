<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| with_context block → OdooClient.call() | Ambient context dict flows from user code into every RPC kwargs |
| Concurrent asyncio tasks → shared OdooClient instance | Two tasks may use with_context simultaneously |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | with_context ambient context injection | accept | By design — with_context is a power-user feature. Context keys are passed verbatim to Odoo. Document that context keys like active_test=False are accepted without validation. |
| T-03-02 | Information Disclosure | _ambient_context ContextVar leaking across tasks | mitigate | ContextVar is task-local by design. asyncio.create_task inherits a copy at creation time; changes in spawned tasks do not affect the parent. Covered by concurrent isolation test. |
| T-03-03 | Tampering | kwargs mutation in call() | mitigate | kwargs is never mutated in-place — always `kwargs = {**kwargs, "context": merged_ctx}`. Callers who pass the same dict object across multiple calls are safe. |
| T-03-04 | Denial of Service | iter_search_read infinite loop | mitigate | Stop condition: `if len(batch) < fetch_size: break` and `if not batch: break`. Both conditions guarantee termination. |
</threat_model>
