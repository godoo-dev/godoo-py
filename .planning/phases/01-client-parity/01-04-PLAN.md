<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| execute_kw → OdooClient.call() | Raw method name from caller crosses into safety guard classification |
| read_binary → base64.b64decode() | Binary data from Odoo crosses into stdlib decoder |
| ref() xml_id parameter | User-supplied string crosses into search_read domain |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | execute_kw — raw method passthrough | mitigate | Routes through call() which calls infer_safety_level(method) and _guard(op). DELETE methods require SafetyContext confirmation. Documented as power-user feature. |
| T-04-02 | Tampering | read_binary — binary field decode | accept | base64.b64decode() is stdlib; decoded bytes are returned to caller without interpretation. Caller is responsible for content validation. Odoo False sentinel handled (returns b""). |
| T-04-03 | Information Disclosure | ref() xml_id injection into domain | accept | xml_id is split on "." and used as exact-match domain values ("module", "=", module), ("name", "=", name). No interpolation. Malformed format raises OdooValidationError before RPC. |
| T-04-04 | Denial of Service | bulk create with large list | accept | No size limit on values list. This is a client library — callers control batch sizes. Document in API that very large lists may exceed Odoo server limits. |
</threat_model>
