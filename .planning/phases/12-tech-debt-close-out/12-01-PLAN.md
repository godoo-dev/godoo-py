<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → external action repos | Actions fetched from third-party GitHub repos at major-tag pins |
| gitleaks-action → git history | gitleaks reads the full commit history; must not have access to runtime secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | actions/checkout@v6, setup-uv@v7, codecov@v6 (bumped actions) | accept | Major-tag pins are the repo convention; SHA pinning would be stronger but contradicts established style. GitHub's tag protection means accidental mutation is unlikely on mature action repos. |
| T-12-02 | Information Disclosure | gitleaks-action scanning git history | mitigate | gitleaks-action@v3 is the official action from the gitleaks org; GITHUB_TOKEN is the only secret injected; no GITLEAKS_LICENSE (not required for personal public repo); full history scan is the intended use case |
| T-12-03 | Information Disclosure | peaceiris/actions-gh-pages@v4 (unpinned to SHA) | accept | Low-value target; publishes only docs site content; no secrets injected beyond GITHUB_TOKEN |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no packages; workflow YAML edits only |

Note: DEBT-02 IS the security control for this phase — it closes the committed-credential threat
surface by scanning full git history on every push. DEBT-01 is CI hygiene; no security surface.
</threat_model>
