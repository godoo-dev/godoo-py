    4. Credential assembly: call config_from_env() then override fields with explicit flag values if provided. Since config_from_env() raises OdooError on missing vars, wrap in try/except OdooError → echo error message to stderr (do NOT include the password value in the message — log only the missing variable names), raise typer.Exit(code=1). Import config_from_env and OdooClientConfig from godoo.client.config inside the function body (deferred import — the same pattern used by other CLI-style entrypoints in this codebase).
    5. asyncio.run(_generate_async(output_path, models, all, config)) — pass the assembled OdooClientConfig, not raw credential strings

    _generate_async(output_dir: Path, models_arg: Optional[str], all_arg: bool, config: OdooClientConfig) -> None:
    1. from godoo.client.client import OdooClient (deferred runtime import)
    2. client = OdooClient(config)
    3. try: await client.authenticate()
    4. Fetch all installed non-transient model names: await client.search_read("ir.model", [("transient", "=", False)], fields=["model"]) → extract ["model"] from each record
    5. Apply fnmatch filter (--models): import fnmatch; patterns = [p.strip() for p in models_arg.split(",") if p.strip()]; selected = [n for n in all_names if any(fnmatch.fnmatch(n, p) for p in patterns)]
       For --all: selected = all_names
    6. Zero matches → `_generate_async` raises `ValueError("No models matched the given patterns.")`. The sync `generate()` wrapper catches `ValueError`, calls `typer.echo(str(e), err=True)`, and raises `typer.Exit(code=1)`. No other zero-match patterns are used.
    7. Introspector and CodeGenerator: introspector = Introspector(client); schemas = await introspector.get_schemas(selected); in_set = frozenset(schemas.keys()); generator = CodeGenerator(introspector, in_set=in_set); generator.write(list(schemas.values()), output_dir)
    8. typer.echo(f"Generated {len(schemas)} model(s) to {output_dir}")
    9. finally: await client.aclose()

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI stdin/env → OdooClientConfig | Credentials enter the process from CLI flags or env vars; must not be echoed, logged, or embedded in error messages |
| --output path → filesystem writes | User-controlled output path; must be an existing directory before any write; no shell expansion |
| --models patterns → fnmatch filter | User-supplied glob patterns are evaluated against model names via fnmatch (stdlib, no eval); patterns cannot execute code |
| Odoo RPC response → generated source | Odoo model names and field data are embedded in generated Python; identifier validation and repr() guard injection points |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Information Disclosure | --password CLI flag | mitigate | typer.Option(hide_input=True) prevents echo in interactive mode; password never passed to typer.echo() or logger; pretty_exceptions_show_locals=False prevents locals dump on exception; credential values are passed as OdooClientConfig fields, not as strings in log messages |
| T-07-06 | Tampering | --output path traversal | mitigate | generate() validates Path(output).is_dir() before any network connection (fail-fast); codegen.write() has a redundant is_dir() check; no shell expansion; output writes only {stem}.py and __init__.py under the user-specified dir |
| T-07-07 | Information Disclosure | config_from_env() error messages | mitigate | OdooError message from config_from_env() names missing variable names (ODOO_URL, ODOO_DB, etc.) but never their values; CLI catches OdooError and echoes only the message string — which must not contain credential values |
| T-07-08 | Tampering | --models patterns evaluated against model names | accept | fnmatch.fnmatch() is stdlib pattern matching with no eval() or shell execution; patterns can only match/not-match model name strings; no code injection surface |
| T-07-09 | Elevation of Privilege | [project.scripts] entry pointing to correct module | mitigate | Entry is "godoo.introspection.cli:app" — matches the exact module path being created; executor must verify the module path matches the actual file location before commit |
| T-07-SC | Tampering | pydantic>=2.13 / typer>=0.26 installs | accept | Package Legitimacy Audit in 07-RESEARCH.md confirmed both packages [OK]; pydantic and typer were already present in the workspace venv as transitive dependencies; adding as direct deps does not introduce new packages |
</threat_model>
