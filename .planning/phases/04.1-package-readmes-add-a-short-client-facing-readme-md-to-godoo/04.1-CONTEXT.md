# Phase 04.1: Package READMEs - Context

**Gathered:** 2026-05-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a short, client-facing `README.md` to each of the three **real** distributions —
`godoo-client` (`packages/godoo`), `godoo-introspection`, and `godoo-testcontainers` —
wire each via a `readme = "README.md"` key in that package's `pyproject.toml`
`[project]` table, and publish **0.2.1** so the three PyPI project pages render a
description instead of the empty pages left after the Phase 04 release.

This phase fixes a packaging defect (empty PyPI pages). It adds no library features and
changes no import surface. The `godoo` meta package (`packages/godoo-meta`) already ships
the family README and renders correctly — it is **out of scope** for new authoring.

</domain>

<decisions>
## Implementation Decisions

### Release trigger (0.2.1)
- **D-01:** Cut 0.2.1 via a **`fix:` conventional commit**, not `docs:`. semantic-release
  is configured with `patch_tags = ["fix", "perf"]` and `minor_tags = ["feat"]` — a
  `docs:` commit would NOT bump the version. Empty PyPI pages are a packaging defect, so
  `fix:` is the honest type and keeps the release fully automated (no config change, no
  manual bump, no `workflow_dispatch`).
- **D-02:** semantic-release bumps **all four** pyprojects in lockstep (they are all
  listed in `[tool.semantic_release].version_toml`), so `godoo-meta` also goes to 0.2.1.
  This is harmless — the meta package already has a README and ships no code.

### README content & shape
- **D-03:** Each short README = **title + one-liner + `pip install` + a tiny runnable
  usage snippet + a link to docs/family**. The one-liner derives from the package's
  existing `pyproject.toml` `description`. The usage snippet is minimal (e.g. construct
  client / call the primary entry point), enough to orient a PyPI visitor without
  duplicating the full docs site.
- **D-04:** Wire each README with `readme = "README.md"` under `[project]` in the
  respective `packages/<pkg>/pyproject.toml`. This is the missing key that left the pages
  empty (only `godoo-meta` currently has it).
- **D-05:** Author the three READMEs **fresh** from the meta README's per-package blocks
  + the pyproject `description` lines. Do **NOT** consult or mirror the godoo-ts package
  READMEs — Python-idiomatic, written independently.

### Cross-linking & meta README
- **D-06:** Each short README links back to the **godoo family** (meta package / GitHub
  repo) **and** the **docs site**. Leave the existing `godoo-meta` README **unchanged** —
  it already lists all packages and renders correctly.

### Claude's Discretion
- Exact wording of one-liners and the precise usage snippet per package (within D-03's
  shape). The client snippet should show the primary `OdooClient` entry point;
  introspection should show `Introspector`; testcontainers should show
  `OdooTestContainer`.
- Exact docs-site and family/repo URLs to link (use the canonical project URLs already
  referenced in the meta package / repo metadata).
- Section ordering and heading style, as long as D-03's elements are all present.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `packages/godoo-meta/README.md`: directly reusable as the per-package block template.
- Each package's `pyproject.toml` already has a `description` field — the README one-liner
  can derive from it for consistency.

### Established Patterns
- uv workspace + hatchling; each package is `packages/<name>/` with its own
  `pyproject.toml` and `src/godoo/<sub>/` tree. The `readme` key belongs under `[project]`.
- Conventional commits drive releases; `fix:` → patch bump → 0.2.1.

### Integration Points
- `readme` key in three `pyproject.toml` files is the functional change that makes PyPI
  render the long description.
- The `fix:` commit is what threads the change onto the existing automated publish path.

</code_context>

<specifics>
## Specific Ideas

- Mirror the meta README's clean per-package block style; keep each README short.
- Client snippet shows `from godoo.client import OdooClient`; introspection shows
  `from godoo.introspection import Introspector`; testcontainers shows
  `from godoo.testcontainers import OdooTestContainer` (matching the meta README's import
  lines).

</specifics>

<deferred>
## Deferred Ideas

- Refreshing/expanding the `godoo-meta` family README — explicitly kept out of scope
  (D-06 leaves it unchanged).
- Adding `docs` to `patch_tags` so future docs-only commits bump patch — rejected for
  this phase (broader side effect); a one-off `fix:` commit is used instead.
- Fuller per-package quickstarts (config, multi-call, error handling) — rejected to avoid
  duplicating / drifting from the docs site.

</deferred>
