## Warnings

### WR-01: Introspection quick-start leaks the client (no `aclose()`)

**File:** `packages/godoo-introspection/README.md:20-23`
**Issue:** The snippet creates a client via `create_client()` but never closes it. The
core `godoo` README correctly demonstrates `await client.aclose()` (README.md:20), and
the project's own `StartedOdooContainer.cleanup()` carries an explicit comment that
`OdooClient` exposes no `__aexit__`, so the underlying `httpx.AsyncClient` pool only
releases on an explicit `aclose()` — "otherwise sockets/fds leak"
(`packages/godoo-testcontainers/src/godoo/testcontainers/container.py:50-54`). A
copy-paste example that omits the documented teardown teaches the leak the codebase
elsewhere warns against.
**Fix:** Add the cleanup line and mirror the core README's `try/finally` intent:
```python
async def main():
    client = await create_client()
    try:
        introspector = Introspector(client)
        schema = await introspector.get_schema("res.partner")
    finally:
        await client.aclose()
```

## Info

### IN-01: Quick-start snippets define `main()` but never run it

**File:** `packages/godoo/README.md:17-21`, `packages/godoo-introspection/README.md:20-23`, `packages/godoo-testcontainers/README.md:17-22`
**Issue:** All three snippets `import asyncio` and define `async def main()` but never
call `asyncio.run(main())`. As written, copy-pasting the block does nothing (and the
`asyncio` import is unused). Minor, but it is the literal "quick start" a new user runs
first.
**Fix:** Append `asyncio.run(main())` at the end of each snippet, e.g.:
```python
asyncio.run(main())
```

### IN-02: Unused result bindings in snippets

**File:** `packages/godoo/README.md:19` (`partners`), `packages/godoo-introspection/README.md:23` (`schema`)
**Issue:** Snippets bind `partners` / `schema` and never reference them. Acceptable as
"here's the call shape," but a trailing `print(...)` would make the example
self-demonstrating and avoid the dangling-variable smell.
**Fix:** Optional — add `print(partners)` / `print(schema)` to close the loop.

### IN-03: Dependency lower-bound pin trails the current version

**File:** `packages/godoo-introspection/pyproject.toml:8`, `packages/godoo-testcontainers/pyproject.toml:8`
**Issue:** Both pin `godoo-client>=0.1.0` while the workspace (including `godoo-client`)
is at `0.2.0`. A `>=0.1.0` floor is valid and not a bug, but if the snippets in these
READMEs rely on APIs that only exist as of 0.2.0, the floor under-specifies the real
minimum. Out of strict phase scope (no version key changed this phase) — flagged for
awareness only.
**Fix:** Consider bumping the floor to `>=0.2.0` if 0.1.0 compatibility is not actually
maintained.
