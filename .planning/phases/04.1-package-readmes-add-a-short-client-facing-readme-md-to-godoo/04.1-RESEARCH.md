## Summary

This phase is a pure packaging fix. Three `pyproject.toml` files under `packages/` are missing
the `readme = "README.md"` key under `[project]`, which is why the three PyPI project pages
are empty. The `godoo-meta` package (`packages/godoo-meta/pyproject.toml`) already has the key
and renders correctly — it is the working reference.

The fix has two mechanical parts per package: (1) add the missing `readme` key to the
`pyproject.toml`, and (2) author a short `README.md` in the package root directory. A single
`fix:` conventional commit covering all six file changes (three `pyproject.toml` edits + three
new `README.md` files) is all that is needed to trigger the automated 0.2.1 release.

The release path is fully automated: `fix:` commit on `develop` → merge to `main` → Test
workflow passes → Release workflow calls `semantic-release version` (bumps all four
`pyproject.toml` versions to 0.2.1, tags, pushes CHANGELOG entry) → `uv publish
--trusted-publishing always --check-url` publishes all four distributions.

**Primary recommendation:** Six file changes in one `fix:` commit (three `pyproject.toml` + three `README.md`). No release plumbing changes needed — it already works.

## Architecture Patterns

### How hatchling resolves `readme`

The `readme = "README.md"` value under `[project]` is a path **relative to the `pyproject.toml`
that declares it**. [VERIFIED: packages/godoo-meta/pyproject.toml — working reference]

```toml
# packages/godoo-client/pyproject.toml  (after fix)
[project]
name = "godoo-client"
version = "0.2.0"
description = "Async Python client for Odoo JSON-RPC"
readme = "README.md"          # <-- THIS is what was missing
...
```

The `README.md` must sit at `packages/godoo/README.md` (sibling of the `pyproject.toml`),
**not** at the repo root. The meta package working reference confirms this layout:

```
packages/godoo-meta/
  pyproject.toml     # readme = "README.md"
  README.md          # the file hatchling actually reads
```

The three packages that need fixing follow identical layout:

```
packages/godoo/
  pyproject.toml     # needs readme = "README.md" added
  README.md          # NEW — to be authored

packages/godoo-introspection/
  pyproject.toml     # needs readme = "README.md" added
  README.md          # NEW — to be authored

packages/godoo-testcontainers/
  pyproject.toml     # needs readme = "README.md" added
  README.md          # NEW — to be authored
```

### README shape (D-03)

Each README follows the per-package block shape from `packages/godoo-meta/README.md`, expanded
with a minimal usage snippet:

```
# <Package Name>

<one-liner from pyproject description>

## Install

\`\`\`bash
pip install <pypi-name>
\`\`\`

## Quick start

\`\`\`python
<import line>
<one or two lines showing primary entry point>
\`\`\`

## Links

- [Documentation](<docs-url>)
- [godoo family](<github-url>)
- [License: LGPL-3.0-or-later]
```

Section names and ordering are within Claude's Discretion (CONTEXT.md). The five mandatory
elements per D-03 are: title, one-liner, `pip install`, usage snippet, links.

## Common Pitfalls

### Pitfall 1: Wrong README path (repo root vs. package root)

**What goes wrong:** Placing `README.md` at the repo root (`C:\dev\godoo-dev\godoo-py\README.md`)
instead of at `packages/godoo/README.md`.
**Why it happens:** It is natural to think of `README.md` as a repo-root file.
**How to avoid:** The `readme` path in `pyproject.toml` is resolved relative to that
`pyproject.toml` file's directory. The working reference (`godoo-meta`) has
`packages/godoo-meta/README.md` alongside `packages/godoo-meta/pyproject.toml`.
**Warning signs:** `hatchling build` would fail with a "file not found" error if the README is
in the wrong location.

### Pitfall 2: Using `docs:` commit type instead of `fix:`

**What goes wrong:** Using `docs: add package READMEs` — semantic-release ignores this commit
type for versioning, no version bump occurs, no publish is triggered.
**Why it happens:** The change is documentation in nature.
**How to avoid:** CONTEXT.md D-01 locks this: use `fix:` because empty PyPI pages are a
packaging defect. `patch_tags = ["fix", "perf"]` — `docs` is absent from this list.
**Warning signs:** After merge to `main`, no new tag appears and no publish workflow fires.

### Pitfall 3: Forgetting to add `readme` key to pyproject.toml

**What goes wrong:** Authoring `README.md` but forgetting the `readme = "README.md"` key in
the `pyproject.toml`. The built wheel will not include the long description and PyPI pages
remain empty.
**Why it happens:** The file alone is not enough — hatchling must be told to include it.
**How to avoid:** Both changes (pyproject + README file) must be in the same commit per D-04.

### Pitfall 4: Including godoo-meta in the authoring scope

**What goes wrong:** Editing `packages/godoo-meta/README.md` or its `pyproject.toml`.
**Why it happens:** It is the same pattern, so it might seem like it needs the same treatment.
**How to avoid:** CONTEXT.md D-06 explicitly excludes it. It already has `readme = "README.md"`
and already renders correctly on PyPI.

### Pitfall 5: Introspection README overpromising functionality

**What goes wrong:** Writing a usage snippet that implies the package is fully functional when
`godoo-introspection` is currently at `Development Status :: 2 - Pre-Alpha`.
**Why it happens:** The snippet naturally mirrors the other two packages.
**How to avoid:** The snippet is valid Python (the public symbols do exist in `__init__.py`
and the classes are instantiable), but the README should acknowledge the pre-alpha status so a
PyPI visitor is not surprised.
