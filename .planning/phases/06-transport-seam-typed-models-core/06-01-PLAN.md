<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → OdooClientConfig | The `transport_factory` field is user-supplied code — the user's own callable runs eagerly inside `OdooClient.__init__`. |
| OdooClient → Transport | All RPC traffic flows through the `_transport` attribute; an alternative transport is responsible for honouring the JSON-RPC contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `Transport` Protocol surface drift vs `JsonRpcTransport` | mitigate | `test_transport_protocol.py` + `mypy --strict` together catch any signature drift the moment it lands |
| T-06-02 | Spoofing | Malicious `transport_factory` returning a fake transport | accept | The factory is supplied by the user's own code — the attack surface is the user's process, not the library; same trust level as supplying `OdooClientConfig` directly |
| T-06-03 | Information Disclosure | Alternative transport leaks session credentials | accept | Out of library scope — alternative transports are user-implemented; library guarantees no behaviour change for the default transport (regression test in existing `test_client.py`) |

This plan introduces no new package installs, no new network endpoints, no new auth flows. The threat surface is the integrity of the Protocol-vs-impl signature contract, mitigated by mypy + the conformance test.
</threat_model>
