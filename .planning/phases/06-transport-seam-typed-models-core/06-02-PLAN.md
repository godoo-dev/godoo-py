Build the typed-models core for the typed-read dispatch path:

1. `godoo.client.typed` (NEW, stdlib-only) — the `OdooModel` Protocol (marker
   requiring `__odoo_model__: ClassVar[str]`) plus the `Ref[T]` generic frozen
   dataclass. Per D-08/D-09 this module is **always importable** without
   pydantic — it is the safe import target for `client.py`'s TypeVar bound
   (Plan 06-03) and for Phase 7 codegen.

2. `godoo.client._pydantic_transform` (NEW, the SOLE pydantic-importing module
   in the `godoo.client` tree) — `OdooBaseModel(BaseModel)` with a
   `@model_validator(mode="before") @classmethod` that performs the three wire
   transforms (D-02 boolean exception, m2o `[id, "Name"]` → `Ref(id, name)`,
   ISO date/datetime strings → typed values), and `derive_partial_model(model,
   fields)` using `pydantic.create_model(__base__=model, ...)` with a
   module-level `(id(model), frozenset(fields))` cache (D-01).

This plan does NOT modify `client.py`, does NOT add the `[typed]` extra, and
does NOT add the isolation guard — Plan 06-03 handles overload dispatch,
packaging, and the subprocess invariant test.

dependency is tolerated at this plan's test-runtime only (developer's `.venv`
will install it because it's a dev/test dep transitively while we develop —
the `[typed]` extra in 06-03 will formalise the user-facing contract).
